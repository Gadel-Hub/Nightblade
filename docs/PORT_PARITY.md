# Port parity checklist

Reference: `proof-of-concept` at `5a8f52038b15e32edd64d6c4a3f35b1e417359bd`
(also `phaser-prototype`). Paths below refer to that ref, not the `main` tree.
Audit used read-only `git branch -a`, `git ls-tree`, `git show`, `git grep`, and
`git log`; no reference files were checked out or restored.

Values are Phaser internal pixels and seconds; +Y points down. Later Unity ports
must deliberately convert distance/speed/acceleration by 32 and reverse Y, while
preserving timing. Player movement is implemented but remains `porting`: Unity runtime
validation is unavailable. See `PLAYER_TUNING.md` and `MOVEMENT_VALIDATION.md`.
No subsystem is marked as manually accepted.
Allowed statuses: `reference only`, `porting`, `parity reached`, `manually accepted`.
